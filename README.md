# Local Heroes Backend

REST API for Local Heroes, built with Node.js, TypeScript, Express, MySQL and [Prisma](https://www.prisma.io/docs) (ORM).

## Getting started

You need [Node.js 24+](https://nodejs.org) and a MySQL server. The easiest way to get MySQL is
[Docker Desktop](https://www.docker.com/products/docker-desktop/).

```bash
npm install              # also generates the Prisma Client
cp .env.example .env     # then set your own passwords and JWT_SECRET in .env
docker compose up -d     # starts MySQL in the background
npm run db:deploy        # creates the tables (applies the migrations)
npm run db:seed          # adds the sports and a demo club (safe to run again)
npm run dev              # starts the API and restarts it when you save a file
```

Check that it works by opening <http://localhost:3000/api/health>. You should see:

```json
{ "status": "ok", "database": "up" }
```

> **Already had the database volume before Prisma was added?** The first start of MySQL runs
> `database/docker-init/01-privileges.sh`, which creates the test database and gives your user the
> rights `prisma migrate dev` needs. It only runs on an empty volume, so reset it once with
> `docker compose down -v && docker compose up -d` (this deletes your local data).
>
> **`npm run db:migrate` fails with `UPDATE command denied`?** Your volume was created before
> the script also allowed changing rows in Prisma's temporary shadow database. Add that right once,
> without losing your data:
>
> ```bash
> docker compose exec db sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "GRANT SELECT, INSERT, UPDATE, DELETE ON *.* TO \"$MYSQL_USER\"@\"%\""'
> ```

## Scripts

| Command                                 | What it does                                                         |
| --------------------------------------- | -------------------------------------------------------------------- |
| `npm run dev`                           | Run the API in watch mode                                            |
| `npm run build`                         | Compile TypeScript into `dist/`                                      |
| `npm start`                             | Run the compiled API from `dist/`                                    |
| `npm test`                              | Run the tests                                                        |
| `npm run typecheck`                     | Check types without compiling                                        |
| `npm run lint`                          | Find code problems (`lint:fix` to auto-fix)                          |
| `npm run format`                        | Format all files (`format:check` to verify)                          |
| `npm run db:migrate -- --name <change>` | After editing `database/schema.prisma`: create and apply a migration |
| `npm run db:deploy`                     | Apply all migrations that haven't run yet                            |
| `npm run db:seed`                       | Add the start data (never deletes anything)                          |
| `npm run db:studio`                     | Browse the database in your browser                                  |
| `npm run token:dev -- <email>`          | Print a login token for a club representative (dev only)             |

`npm test` uses the separate `local_heroes_test` database, so MySQL must be running. Your
development data is never touched by the tests.

## Project structure

```text
database/
  schema.prisma        All tables, columns and relations (edit this, then run db:migrate)
  migrations/          SQL generated by Prisma from the schema. Commit these, never edit them
  seed.ts              Start data (sports, demo club)
  docker-init/         Runs once when the MySQL container is first created
prisma.config.ts       Tells the Prisma CLI where the schema, migrations and seed are
scripts/               Small developer tools
src/
  config/              Environment variables, validated at startup
  controllers/         Read the request, call a service, send the response
  db/                  The shared Prisma Client
  generated/prisma/    Generated by Prisma (not in git, recreated by `npm install`)
  errors/              Custom error classes
  middleware/          Code that runs around requests (errors, 404s, auth)
  repositories/        Database queries with Prisma, one file per table or feature
  routes/              Map URLs to controllers
  services/            Business rules
  types/               Shared TypeScript types
  validators/          Zod schemas that check incoming data
  app.ts               Creates and configures the Express app
  server.ts            Starts the app
tests/                 Automated tests
```

## How a request flows

```text
route -> controller -> service -> repository -> MySQL
```

Each layer only talks to the next one, so database code stays in repositories and no service
touches `req` or `res`.

## Adding a new feature

**Activities are the full working example.** Read [docs/activities.md](docs/activities.md): it
walks through one request from route to database and lists the steps to copy for a new feature.

In short, to add for example clubs:

1. Add the model in `database/schema.prisma` and run `npm run db:migrate -- --name add_clubs`.
2. Add the queries in `src/repositories/clubs.repository.ts`.
3. Add the rules in `src/services/clubs.service.ts`.
4. Add the input schemas in `src/validators/clubs.validator.ts`.
5. Add the response types (DTOs) in `src/types/clubs.types.ts`.
6. Add the handlers in `src/controllers/clubs.controller.ts`.
7. Add the URLs in `src/routes/clubs.routes.ts` and register them in `src/routes/index.ts`.
8. Add tests in `tests/clubs.test.ts`.

Import other layers as a namespace, so every call shows which layer it goes to:

```ts
import * as activitiesRepository from '../repositories/activities.repository';

await activitiesRepository.findActivityById(id);
```

Prisma always sends values separately from the SQL, which protects against SQL injection. If you
ever need raw SQL, use the tagged template `` prisma.$queryRaw`... ${value}` ``, never
`$queryRawUnsafe` with joined strings.
